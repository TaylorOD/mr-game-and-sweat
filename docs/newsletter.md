# Newsletter operations

The newsletter uses Brevo Free. Mailchimp was closed on November 14, 2026.

## Account and signup

- Account: the separate Mrgameandsweat Brevo account, not Reachoutt.
- Audience/list: `Mr. Game and Sweat` (created empty; no subscriber imports).
- Form: `Mr. Game and Sweat newsletter`.
- Double confirmation email is selected using Brevo's double opt-in template. Only confirmed contacts may join the list.
- Sender: `Mr. Game and Sweat`, `mrgameandsweat@gmail.com` (verified).
- Gmail cannot be authenticated as a domain you own. Brevo warns about freemail deliverability. A future custom-domain sender requires DNS authentication and sender verification.
- The approved postal footer address belongs in Brevo, not this public repository.
- `_includes/newsletter.html` contains only the public form endpoint, Brevo validation hooks, locale, and the `email_address_check` honeypot. No API key is needed.
- `_layouts/default.html` displays one signup form per page; styling is in `assets/css/theme.scss`.
- Keep the entire public embed configuration together when regenerating a form. Do not reuse Mailchimp identifiers or spam fields.

## Sending and limits

Automatic sending is OFF. The draft RSS integration is named `Mr. Game and Sweat weekly digest`.
Proposed cadence: Sunday 9 a.m. America/Denver, pending owner approval.
Free costs $0, includes Brevo branding and 300 total sends/day (including confirmations/tests). A campaign over 300 recipients does not automatically reach everyone; monitor list size and remaining quota before activation. Do not start a paid trial or upgrade without approval.

## Feed and backfill

The live `/feed.xml` is a valid Atom feed generated by jekyll-feed, with ten entries at verification. Brevo loaded the URL, but a rendered email has not yet been validated.
The feed includes published and updated timestamps. Before activation, verify the integration uses publication dates and stable item IDs, that editing an old review does not resend it, and that a newly added backdated review is not treated as new. Do not assume that loading a feed proves these behaviors.
Do not activate against an untested historical feed. If Brevo cannot reliably exclude historical content, add a dedicated RSS 2.0 newsletter feed with an explicit launch cutoff and opt-out flag before enabling it. Confirm its first digest contains only intended new content. Keep the integration inactive while backfill behavior remains unverified.

## Required launch checks

- Inspect the actual built site at desktop and phone widths. CI captures `newsletter-screenshots` artifacts.
- Approve the test recipient before sending any email.
- Submit the website form; verify pending status, receipt of the confirmation email, confirmation link, and membership in the correct list.
- Review the confirmation email's sender/branding before launch.
- Customize the RSS template: brand name, logo/colors, concise review excerpts and links, approved postal address, reply-to address, and working unsubscribe link.
- Send a sample only to the owner-approved test address and check the actual received message.
- Follow the unsubscribe link; verify the contact is excluded from future sends.
- Obtain cadence and preview approval, then enable the integration and record the activation date/time here.

## Maintenance

Review bounces, complaints, quota, and subscriber count regularly. Keep suppression/unsubscribe state in Brevo; do not re-import unsubscribed people. Pause the integration before feed changes or content migrations. Use the same stable article URLs and original publication timestamps. Keep passwords, verification codes, API keys, subscriber exports, and account screenshots out of this repository.
